# Rowan BFF v1 (Plan 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `apps/bff`, a TypeScript service that gives browser users email/password accounts, cookie sessions, agent API-key management, and an authenticated pass-through to the Go core's `/v1` API.

**Architecture:** The BFF shares the core's PostgreSQL database; the Go core stays the only migrator (one new migration, `0006`). A browser session **is** a core API key: on login the BFF inserts an `api_keys` row with `kind='session'`, a `user_id` and an `expires_at`, and puts the plaintext token in an HttpOnly cookie. Proxied `/api/v1/*` calls forward that token as `Authorization: Bearer`, so the core's existing auth, rate limits, ledger, idempotency and export gating apply unchanged, and `export_audits.user_or_key_id` resolves to a user. No session table, no stored plaintext, no encryption secret.

**Tech Stack:** Node 24 (native TypeScript type stripping, `node --test`), TypeScript strict (`tsc --noEmit` only), `node:http`, `node:crypto` (scrypt, sha256), `pg`, `zod`. Dev: `typescript`, `@types/node`, `@types/pg`. No HTTP framework, no ORM, no test framework.

**Spec:** `Architecture.md` §1 (BFF: auth/session handling, API key management, typed client calls to Go), §2 (`users`, `api_keys` with caps); `PRD.md` §2 and §7 milestone 3 (capped agent keys); `AGENTS.md`. Plan 1 (`docs/superpowers/plans/2026-11-20-rowan-core-v1.md`) defines the core API this plan proxies. Executors read all of them.

## Program Context

Plans 1 (core) and 4 (connectors) are merged on `main`. This plan depends only on Plan 1. Plan 3 (`apps/web`) will consume this plan's `/api/*` surface and `apps/bff/src/core/schemas.ts`. Billing (Plan 5) is out of scope: a new workspace starts with zero credits; seed credits with `rowanctl credits topup`.

## Global Constraints

- Plan 1 Global Constraints still apply (thresholds, `data_quality_status`, FIFO, idempotency, export policy). The BFF never re-implements them; it forwards to the core.
- Node `>=24`; `package.json` `"type": "module"`, `"engines": {"node": ">=24"}`. Source runs directly as `.ts`; imports use explicit `.ts` extensions.
- `tsconfig.json`: `strict`, `noEmit`, `noUncheckedIndexedAccess`, `allowImportingTsExtensions`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `module`/`moduleResolution` `nodenext`, `target` `es2024`. No `enum`, `namespace`, or parameter properties (type stripping rejects them).
- Every request body and every env var is parsed with `zod`; no `any`, no unvalidated `JSON.parse` result reaches logic.
- Error body shape is identical to the core: `{"error": {"code": "<snake_case>", "message": "<text>"}}`. 5xx bodies never carry internal error text.
- SQL is parameterized (`$1`…) only. Postgres `bigint` columns come back from `pg` as strings; convert with `Number()` only where the value is bounded (caps ≤ 1,000,000).
- Env vars (exact names): `DATABASE_URL`, `ROWAN_CORE_URL`, `ROWAN_WEB_ORIGIN`, `PORT` (default `8081`), `ROWAN_COOKIE_SECURE` (default `true`; `false` only for local http).
- Cookie: name `rowan_session`; `HttpOnly; SameSite=Strict; Path=/; Max-Age=1209600` (14 days), plus `Secure` unless `ROWAN_COOKIE_SECURE=false`.
- Tokens: session `rk_sess_` + base64url(32 random bytes); agent `rk_live_` + base64url(32 random bytes). Stored only as `key_hash = sha256(token string)` (raw 32 bytes in `bytea`), matching `api.HashKey` in Go.
- Session key row: `kind='session'`, `label='session'`, `monthly_spend_cap=9223372036854775807`, `rate_per_minute=300`, `expires_at = now + 14 days` (absolute, not sliding).
- Agent key bounds: `label` 1–100 chars after trim; `monthly_spend_cap` integer 0–1,000,000; `rate_per_minute` integer 1–600, default 120.
- Passwords: 12–256 chars. Hash: `scrypt` N=131072, r=8, p=1, 16-byte random salt, 32-byte key, `maxmem` 256 MiB; stored as `scrypt$131072$8$1$<salt b64url>$<hash b64url>`; verify with `timingSafeEqual`.
- Emails: trimmed, lowercased, `z.email()`, max 254 chars; unique on `lower(email)`.
- CSRF: every request under `/api` with a method other than `GET`/`HEAD` must carry `Origin` exactly equal to `ROWAN_WEB_ORIGIN`, else `403 origin_forbidden`. Checked before auth and before reading the body.
- The BFF never accepts `Authorization` headers from clients; agents call the core directly with `rk_live_` keys.
- BFF-owned endpoints (`/api/auth/*`, `/api/me`, `/api/keys*`) do not take `Idempotency-Key` (they are not billable; replaying key creation would require storing plaintext). Proxied `/api/v1/*` calls forward the client's `Idempotency-Key` unchanged.
- Request bodies over 1 MiB (1,048,576 bytes) → `413 payload_too_large`, never forwarded.

## Review Focus

1. **A logged-out or expired session cookie replayed straight at the core** must get `401`; logout and expiry must not be BFF-only checks. (Task 1 Go test; Task 6 e2e.)
2. **Revoking another workspace's key, or a session key, through `/api/keys/{id}`** must be `404` and change nothing. (Task 4 test.)
3. **A cross-site form or fetch** (foreign or missing `Origin`) on any mutating `/api` route, including login and the proxy, must be `403` before any side effect. (Task 2 test.)
4. **Login with an unknown email** must return the same status and body as a wrong password, and still run a scrypt verify. (Task 3 test.)
5. **The core is down or returns garbage** — the proxy must answer `502 core_unavailable` without leaking the connection error. (Task 5 test.)

- Produces: `ANY /api/v1/{rest}` (query string kept) → `${coreUrl}/v1/{rest}`.
  - No `rowan_session` cookie → `401 unauthorized` without calling the core. Otherwise forward the cookie value as `Authorization: Bearer <token>`; the core authenticates it (no BFF DB lookup).
  - Request headers forwarded: `Content-Type`, `Idempotency-Key`, `Accept` only. Body forwarded as-is for non-GET/HEAD (≤ 1 MiB; larger → `413 payload_too_large`, core not called).

  - Network error, timeout (30 s via `AbortSignal.timeout(30000)`) → `502 core_unavailable` / `"core service unavailable"`; the error is logged, not returned.
